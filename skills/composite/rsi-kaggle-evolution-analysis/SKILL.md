# Kaggle 开源方案进化分析

目标是判断**下一步最值得做什么**，不是再列一份可能用到的方法清单。输入是目标比赛、指标与方向、当前有效基线、可取得的 Top 公开方案、剩余预算和当前阶段。输出是可交接的优化方向记录：进化阶段、证据、假设、优先级、成本和停止条件。

该方法来自 71 场“我提出方案 vs Top-20 开源方案”的对比。核心结论不是方向覆盖不够，而是**优先级、验证协议、数据/外部先验、metric 复现、后处理和工程约束**经常决定名次。开源方案最常见的进化顺序是：

> 强基线 → 正确验证 → 数据/先验杠杆 → 互补模型 → 融合校准 → 后处理 → 推理工程

因此分析时先定位当前方案处于哪一阶段，再选择下一项；不默认“换更大的模型”。

## 输入与输出

输入：

- 比赛 slug、任务类型、metric 和优化方向。
- 当前有效基线及真实评估记录；没有有效基线时先补基线。
- 公开方案证据：`rsi-kaggle-open-sota` 的发现结果，或已冻结的 Top-20 notebook 源码/摘要/版本。
- 验证约定、算力、时限、提交限制和剩余预算。

输出为任务工作区内的 `evolution_decision.md`，至少包含：

1. 当前进化阶段和判断依据。
2. Top 方案按“阶段”而不是按分数归档的结果。
3. 当前基线与开源主线之间的证据缺口。
4. 2–5 个可证伪的优化假设，按预期收益/成本/风险排序。
5. 每个假设的验证方式、预计资源和停止条件。
6. 下一步动作：继续实验、先修验证/数据、回退或收尾。

## 1. 先把评分和验证变成可信对象

使用 `rsi-validation-design` 确认划分、分组、时间窗口和泄漏风险；使用 `rsi-kaggle-open-sota` 取得带时间的 Public Score、指标方向和公开候选。不能只看标题、投票数、README 自述或作者给的 CV 就判断强弱。

本地 metric 必须先复现或明确标注为未复现。很多榜单的阈值、截断、去重、校准、拓扑和格式规则就是提分点；分析阶段应把 metric 当作可优化对象，而不是最后才调用。

## 2. 为 Top 方案建立进化链

对每个公开候选，按以下标签归档：

| 标签 | 观察内容 | 常见证据 |
|---|---|---|
| `baseline` | 最先生效的强基线 | GBDT、线性、预训练 backbone/embedding、规则 bot、局部搜索 |
| `validation` | 与测试集更接近的验证协议 | 按 site/patient/scaffold/date/play/well/family 分组，或 purge/embargo |
| `data_prior` | 数据表示、外部先验、标签清洗、泄漏审计 | 赔率、538、公开解、预训练 embedding、IMU-only、相邻帧去重 |
| `complementary_model` | 只加入误差相关性低的第二个模型 | GBDT+NN、CNN+Transformer、embedding+树、规则+搜索 |
| `fusion_calibration` | OOF/rank/加权融合、阈值、校准 | stacking、Borda/RRF、QWK/F-beta/Brier/Sharpe 校准 |
| `postprocess` | 拓扑、去重、3D NMS、质量守恒、格式修复 | 后处理当模型的一部分 |
| `engineering` | 推理/提交约束、fallback、打包、恢复 | vLLM/AWQ、ONNX/OpenVINO、kernel pool、超时和内存 |

不要把“有分数”当成“方法有效”。同一篇 notebook 的最新版本可能退步；最高分应绑定到 `rsi-kaggle-open-sota` 确认的历史最佳版本。若需要本地执行原版，再使用 `rsi-kaggle-reproduce`。

## 3. 定位当前阶段

按下面顺序，选择第一个尚未完成且证据不足的阶段作为主要缺口：

1. **有效提交和 metric 复现**：能否本地生成合法产物并复现评分口径。
2. **强笨基线**：是否已有比随机/空提交更稳定、可比较的 baseline。
3. **验证协议**：切分是否模拟部署或测试分布，泄漏是否审计。
4. **数据/先验杠杆**：是否有尚未使用的正确数据表示、外部先验、标签清洗。
5. **互补模型**：现有方案是否只有一个模型，或候选之间误差高度相关。
6. **融合、校准、后处理**：是否把阈值、去重、拓扑、格式修复纳入主循环。
7. **工程和停止**：是否能在约束内完成推理与提交，是否有明确的停止规则。

阶段判断必须来自已观察证据；缺少证据时标为未知，不能因为“看起来应该完成”就跳过。

## 4. 比较开源进化链，而不是比分数

把 Top 方案按阶段归类后，回答以下问题：

- 领先方案的主线是“更强模型”还是“更好的验证/数据/后处理/工程”。
- 当前基线与领先方案在哪个阶段差距最大，且该差距可以在剩余预算内验证。
- 哪些高分方案依赖测试数据、公开解、泄漏或评测器特性，不能作为通用方向。
- 哪些方案只是幸存者，不能把 Top-20 当成完整搜索空间。

用 `rsi-error-analysis` 对当前基线做切片诊断，优先找到证据最强的短板。不要同时列五个改动，优先选择能直接回答“为什么落后”的那个。

## 5. 生成假设并排序

每条假设写成：

> 改动是什么 → 为什么预期有效 → 相对哪个基线 → 如何验证 → 预计成本 → 停止条件。

排序使用预期信息收益与成本比，而不是方法新颖度。按任务类型参考以下第一优先级：

| 任务类型 | 先做 | 再做 | 不要先做 |
|---|---|---|---|
| 小数据表格 | GBDT + 特征工程 + 校准 | OOF stacking、外部先验 | 大 Transformer、端到端深度模型 |
| 时序/金融 | leak-safe CV + lag/截面特征 + GBDT | 在线更新、风险缩放 | 单纯 LSTM/Transformer |
| 图像分类/回归 | 预训练 backbone/embedding + 轻量头 | 微调、TTA、融合 | 从零训练大 CNN |
| 3D/医学影像 | 2.5D/3D 混合 + 切片聚合 | 后处理、拓扑、标定 | 只看 3D U-Net |
| 文本分类/排序 | DeBERTa/LLM embedding + 强基线 | 两阶段检索、LoRA、logits 约束 | 一上来全参微调大模型 |
| 机器翻译 | 专用 seq2seq/ByT5 + 多候选 | MBR、规则后处理 | 只靠通用 LLM few-shot |
| 音频 | 预训练 embedding/SED | SSM/蒸馏、TTA | 从零训练大音频模型 |
| Agent/游戏 | 规则 bot + 搜索 + replay | 局部 PPO、对手池 | 冷启动端到端 RL |
| 组合优化 | SA/局部搜索/构造启发式 | 多起点、按样本集成 | MILP/RL 硬套大规模 |
| 研究/评审赛 | 窄问题 + 强基线 + 消融 | demo、证据链、叙事 | 堆模块、堆模型 |

## 6. 加入方法前的三个门禁

每个候选改动必须至少通过以下三项检查：

1. 能否在已复现/可信的本地 metric 上稳定提升。
2. 是否破坏现有验证协议，或引入新的泄漏。
3. 是否能在算力、显存、时限和提交规则内完成。

任何一项回答不了，先不加入；需要先补证据，而不是先跑模型。

## 7. 停止规则

- 连续两次改动没有超过噪声水平的提升：停止优化，冻结当前有效候选。
- 新模型与现有模型误差相关性高：不加模型，转向数据、验证或后处理。
- 公榜提升但本地 CV 不升：先怀疑泄漏或公榜噪声，不继续扩大该方法。
- 工程复杂度上升但预期收益很小：不做，改为巩固提交和回退路径。
- 预算耗尽：用 `rsi-experiment-review` 比较现有候选并收尾。

## 8. 交接

该技能只负责判断方向和产出假设，不负责正式提交、隐私验证或替代可信评分。最终候选选择、真实评估和提交由 System 控制。

把 `evolution_decision.md` 交给后续实验/优化流程时，保留：

- 数据划分和 metric 协议 ID。
- 当前基线候选 ID、分数和产物哈希。
- 每个假设的状态：未做、进行中、已验证、已排除、无预算。
- 未验证项和证据缺口。

只有 `rsi-experiment-review` 认可的真实评估结果能改变候选顺序；训练分数、自报分数和公开方案的自述不能替换 System 评分。
